# `routes_index.csv` — column reference

Generated by `scripts/list_routes.py` (via `scripts/routes_lib.py`) from
`matched_data_flat_2020_01.parquet` + `metadata_closest_ems_to_train_stations.csv`.
Regenerate with:

```bash
source .venv/Scripts/activate
python scripts/list_routes.py
```

One row = one **route** = an origin → destination pair for a given `trainType`,
aggregated over every run (`departureDate` + `trainNumber`) of that route in the
source month(s). All delay statistics are computed **per run first** (each run's
average `ARRIVAL` delay, early arrivals clamped to 0 — see CLAUDE.md's delay
convention), then aggregated across the route's runs — never averaged directly
over individual station events.

"On time" = ≤ 5 min late. Delay severity buckets used throughout: **on time**
(≤ 5 min), **minor delay** (5–15 min), **major delay** (> 15 min).

## Identity

| Column | Meaning |
|---|---|
| `id` | Route identifier: `<from>-<to>-<trainType>`, e.g. `HKI-TKU-IC`. |
| `from` / `to` | Origin / destination station short code. |
| `fromName` / `toName` | Origin / destination station name. |
| `trainType` | Train type of this route's runs (e.g. `IC`, `S`, `HDM`). |
| `runs` | Number of individual train runs that make up this route in the month. |

## Delay — central tendency & tails

| Column | Meaning |
|---|---|
| `avgDelay` | Mean of each run's average arrival delay (minutes). The headline number, but sensitive to outliers. |
| `medianDelay` | Median of the same per-run values (minutes). More robust than `avgDelay` — compare the two to gauge skew (a much higher mean than median means a few very late runs are dragging the average up). |
| `p90Delay` | 90th percentile of per-run average delay (minutes). 90% of runs were at or below this; the worst 10% of runs were later. Shows how bad the bad days get. |
| `maxDelay` | The single worst run's delay (minutes) — the true outlier, not just a percentile. |
| `delayStdDev` | Standard deviation of per-run average delay (minutes). Two routes can share the same `avgDelay` but differ a lot here: a low value means "consistently about this late," a high value means "usually fine, occasionally very late." |

## Delay — severity buckets

| Column | Meaning |
|---|---|
| `onTimePct` | % of runs with average delay ≤ 5 min ("on time"). |
| `pctMinorDelay` | % of runs with average delay > 5 and ≤ 15 min. |
| `pctMajorDelay` | % of runs with average delay > 15 min. |
| `avgMinorDelay` | Mean delay (minutes), computed only over the runs that fall in the minor-delay bucket. `n/a` if the route has no runs in that bucket. |
| `avgMajorDelay` | Mean delay (minutes), computed only over the runs that fall in the major-delay bucket. `n/a` if the route has no runs in that bucket. |

`onTimePct + pctMinorDelay + pctMajorDelay` sums to 100% (rounding aside) for
every route that has at least one run with delay data.

## Other run quality

| Column | Meaning |
|---|---|
| `cancelledPct` | % of the route's runs that had at least one cancelled stop. |
| `worstDay` | `departureDate` of the run with the highest average delay. |
| `firstDate` / `lastDate` | Earliest / latest `departureDate` among the route's runs. |
| `month` | Source month (`YYYY-MM`), e.g. `2020-01`. |

## Stops

Restricted to stations with `passengerTraffic == True` in
`metadata_closest_ems_to_train_stations.csv` — freight-only / non-passenger
stops are excluded even though the train may technically pass through them.

| Column | Meaning |
|---|---|
| `stationCount` | Number of passenger stations in the route's *typical* stop sequence (see below). |
| `patternShare` | % of the route's runs whose passenger-stop sequence exactly matches that typical sequence. 100% means every run stopped at exactly the same passenger stations in the same order; a lower value means some runs skipped or added stops. |
| `stops` | JSON array, one object per passenger station in travel order — see below. |

"Typical" = the most common exact passenger-stop sequence across the route's
runs (ties broken by whichever sequence was encountered first). If a route has
no runs with any passenger stops, `stops` is `[]` and `stationCount` is 0.

### `stops` — per-station fields

Each entry in the `stops` array has the **same statistics as the route-level
table above**, but scoped to just that one station (still restricted to this
route's own runs):

| Field | Meaning |
|---|---|
| `order` | 0-based position in travel order (0 = origin). |
| `code` | Station short code. |
| `name` | Station name. |
| `runs` | How many of *this route's* runs have an `ARRIVAL` event with a usable delay value at this station. Usually close to (but not always equal to) the route's total `runs` — some runs skip stops. The origin is always `0` (a run's first stop only has a `DEPARTURE` event, no `ARRIVAL`). |
| `avgDelay` / `medianDelay` / `p90Delay` / `maxDelay` / `delayStdDev` | Same meaning as the route-level columns (see above), computed only from this station's arrivals within this route. |
| `onTimePct` / `pctMinorDelay` / `pctMajorDelay` | Same bucket shares as the route-level columns, computed only from this station's arrivals within this route. |
| `avgMinorDelay` / `avgMajorDelay` | Mean delay within each bucket, at this station. `null` if this station had no arrivals in that bucket. |
| `cancelledPct` | % of this station's `ARRIVAL` events (cancelled ones included in the denominator, unlike the other fields here) that were cancelled. |

All fields are `null` (and `runs` is `0`) when the station has no `ARRIVAL`
events at all within this route's runs (the origin, or a station only ever
skipped).

These numbers are scoped **to this route's own runs only** — the same
physical station can appear in other routes' `stops` with different figures,
because it's being fed by a different set of trains. Reading `avgDelay` down
the list shows where along the route delay tends to build up (or recover).

## Notes / edge cases

- A route whose runs are all fully cancelled before reaching an `ARRIVAL` event
  has `nan` (printed as `n/a` by the CLI) for every route-level delay column,
  and every `stops` entry has `runs: 0` / `null` delay fields — but
  `cancelledPct` is still populated.
- Not every route ends in Finland — a handful (e.g. `HKI-PTR-AE`, to Pietari /
  St Petersburg) run through Russian border stations that aren't in the
  metadata CSV, so those don't count toward `stationCount`/`stops`.
